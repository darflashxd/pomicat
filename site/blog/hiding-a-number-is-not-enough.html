Hiding a number is not enough

People ask AI assistants about money all the time. How much should I save? Can I afford this rent? The answer is useful, so they share it with a partner, a friend or a group chat. Most of them know to hide the salary first.

Here is what that usually looks like:

User: My salary is [REDACTED] a month. If I save 20%, how much is that?
Assistant: Saving 20% means $1,000 per month, leaving $4,000 for expenses.
           Over a year that adds up to $12,000.

The salary is gone, but the reply still holds it. $1,000 divided by 20% is $5,000. So is $4,000 divided by 80%, and $12,000 divided by 12 and then by 20%. Three different lines all point at the same number.

We measured it

We wrote 40 fictional chats like this one, each with a salary and an answer that uses it. Then we redacted them three ways and asked LLMs to find the salary:

RedactionSalary recovered
Naive: hide only the salary100%
Presidio, a widely used PII tool100% (left visible, or recovered from the reply)
PomiCat: hide the salary and the figures derived from it0 of 160

We ran DeepSeek V4 Pro, Claude Sonnet 5.5 and Claude Haiku 5.5 in English, and Sonnet again on Indonesian chats in Rupiah. Every model found every salary after naive redaction. A single line such as "saving 25% gives $600" was enough. After PomiCat, every model answered that there was not enough information.

The chats are templated and fictional, so this shows the attack works, not how often it happens in real conversations. The full results list the limits.

What PomiCat does about it

When you hide an amount, PomiCat looks for the numbers around it that are ratios, monthly or yearly versions, projections, sums or differences of it, across every message. Those are hidden too. Before you share, it runs the same kind of attack on the copy and tells you if anything can still be worked back out.

It covers specific kinds of arithmetic, not every possible inference. Birth years from ages and dates from weekday clues ("the Tuesday after the 14th") are handled the same way.

Then there is the link

In 2025, shared ChatGPT conversations started turning up in Google results. A share page is just a web page, and anything a crawler can read, it can index.

A PomiCat link looks like https://relay/v/<id>#<key>. Browsers never send the part after # to the server, and neither do crawlers. The relay only ever stores ciphertext. Our test suite fetches chat and Word document links as Googlebot and checks that neither the page, the API nor the relay's storage contains the text or the key.

That does not make a link secret. Anyone holding the full link can open it until it expires or you revoke it. It means search engines get nothing readable from it.

Try it

git clone https://github.com/darflashxd/pomicat.git
cd pomicat
node bin/pomicat.js invert examples/chat_naive_redacted_en.txt

No account, API key or model download needed. Then install the extension and try it on a chat of your own, with fictional numbers first.
