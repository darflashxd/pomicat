Shared AI chats ended up in Google.
PomiCat links can't be read.

PomiCat hides what is private in an AI chat or a document, including the numbers that would give it away, then encrypts the copy in your browser. The key stays after the #, so crawlers and the server get nothing they can read.

Install

Chrome, Edge and Brave

  1. Download the Chrome ZIP from the latest release and extract it.
  2. Open chrome://extensions, turn on Developer mode and choose Load unpacked.
  3. Select the extracted folder, then refresh any chat or Word tabs that were already open.

The model and its runtime are bundled. You do not need Python, a model download or an API key to use the extension.

Firefox

Download the Firefox ZIP from the release, open about:debugging#/runtime/this-firefox, choose Load Temporary Add-on and pick the manifest.json inside. Temporary add-ons are removed when Firefox restarts.

From source

git clone https://github.com/darflashxd/pomicat.git
cd pomicat
python tools/build_extension.py   # writes Chrome and Firefox ZIPs to dist/

Share a chat

  1. Open a conversation on ChatGPT, Claude, Gemini or DeepSeek and click the PomiCat button in the bottom-right corner.
  2. Check that every message was read. The original and the copy others will see sit side by side.
  3. Click a highlight to hide or restore it, or select any text to hide it yourself. Some model suggestions start ticked when they look like a credential or a confident name, so check each one.
  4. Pick who will read it and how amounts are handled, then Create Private Link. Choose an expiry, and burn after reading if you want a single view.
  5. You can revoke the link later from the extension's toolbar page.
Detection can miss things. Read the copy before you share it. An empty attack check means the supported checks found nothing, not that the copy is anonymous.

Share a Word document or Google Doc

  1. Open a saved .docx in Word Online, or a Google Doc, and click the PomiCat button.
  2. PomiCat reads a separate copy through your current SharePoint or Google session (Google Docs are exported as DOCX). Your original is never changed.
  3. Review the highlights. Tracked changes, comments and document properties are removed unless you keep them.
  4. Images are reviewed by hand: drag over an area and the pixels are replaced, not covered.
  5. Create sanitized DOCX, then download it or create an encrypted link (24 hours, 3 days or 7 days, revocable).

Links are limited to 512 KiB of ciphertext, so documents with many images are better downloaded. Text inside images is not detected automatically.

Protect before sending

The chip above the chat box is a separate, optional feature. It is off by default.

ModeWhat happens
OffYour prompt is sent as typed. Sharing still works.
Protect amounts onlyPersonal amounts are sent as <S1>, <S2>. Formulas in the reply are computed on your screen.
Protect IDs + amountsIDs and credentials are replaced too, and your own names and places when the local model is ready.
The chat site can still read what you type before you press send. This feature changes what is submitted, not what the page can see.

How it works

Read the conversation or document
  -> rules, context checks and a local model mark private details
  -> arithmetic checks find numbers that reveal a hidden value
  -> you review, hide or restore
  -> AES-256-GCM encryption in your browser
  -> ciphertext goes to the relay; the key stays after the #

The bundled model is gravitee-io/bert-small-pii-detection (INT8, English-focused, about 28.7 MB). Rules cover IDs, bank accounts, cards, phone numbers, credentials and Indonesian formats such as NIK and Rupiah amounts.

Limits

  • The model is English-focused. Other languages rely mostly on rules.
  • Text in images, attachments and every field of pasted logs are not covered.
  • Combinations of details (job, town, age) can still point to a person.
  • Screenshots and photos of a shared copy cannot be prevented.
  • If a real password was already sent to a service, change it. Redacting a later share does not remove it there.

CLI and proxy

Node.js 18 or newer, no extra dependencies.

node bin/pomicat.js invert examples/chat_naive_redacted_en.txt     # recovers $5,000
node bin/pomicat.js redact examples/chat_original_en.txt | node bin/pomicat.js invert
node bin/pomicat.js proxy --port 8788 --upstream https://api.openai.com

The proxy redacts supported text fields in OpenAI and Anthropic requests before forwarding them. It does not restore responses and does not cover images or files. The CLI uses the rules, not the browser model.

Run your own relay

python relay/server_local.py
node bin/pomicat.js share examples/chat_original_en.txt --burn --ttl 3600 --relay http://127.0.0.1:8787

Cloudflare Worker and D1 setup is in DEPLOY.md.

Troubleshooting

A share link opens a blank page

The installed extension is older than the page. Reload it in chrome://extensions, approve the relay host if Chrome asks, then open the link again.

Word says "Link was not created"

The message under the button names the cause. For a file over 512 KB, use Download DOCX. For "too many uploads", wait about a minute.

"Open conversation" appears before the chat

On purpose. Link scanners open links without a person, and a burn-after-reading link would be used up. Your click is the first read.

FAQ

Does the original change?

No. PomiCat reviews a copy. The optional before-sending mode is the only feature that changes what you submit.

Does the recipient need the extension?

No. Without it the hosted viewer decrypts the link, and its operator must be trusted. With it, the extension's own viewer is used.

Who can read a link?

Anyone with the complete link, including the part after #. Expiry and revocation stop later access, not copies already saved.

Can it miss things?

Yes. Always read the copy before sharing.
